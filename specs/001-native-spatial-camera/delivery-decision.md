# Delivery decision: patch series vs plugin function hooks (T067, V-21)

**Status**: evidence complete for the spike; the decision is presented at the Feature 001 gate (T071) for user approval.
**Rule being applied** (master plan §A item 4, DV3-01): if the plugin-hook port passes the **same visual + input
suite**, ship the plugin on stock Hyprland; otherwise ship the patched Hyprland side by side (own prefix, own session,
stock Hyprland stays the fallback).

## What the spike is

`platform/plugin-spike/` (nested-only, never loaded into the host) reproduces patches 0002–0009 on the
stock-from-source prefix (Hyprland 0.56.2 `efb5099`, binary `927f6f64…`) with `createFunctionHook`:

| Part | Size | How |
|---|---|---|
| Camera state, render modifier, input helpers (`Camera.cpp/.hpp`) | 262 lines | Port of `src/hyprvx/*` from 0001/0002/0004/0006; the camera lives in a map keyed by monitor id (a plugin cannot add a `CMonitor` member) |
| Dev control (`DevControl.cpp`) | 111 lines | `hyprctl hyprvx-dev` through `HyprlandAPI::registerHyprCtlCommand` (dev-control contract unchanged, tests unchanged) |
| Wrapper hooks (`RenderHooks.cpp`) | 131 lines, 7 hooks | Call the original and add what the patch adds: `renderMonitor` (noSimplify), `renderAllClientsForWorkspace` + `renderWorkspaceWindows` (camera hint), `isDSBlocked`, `isSolitaryBlocked`, `damageBox`, `damageWindow` |
| Copied functions (`copied/*.cpp`, generated by `gen_copies.py`) | 2394 lines generated, about 1700 of them upstream function bodies; 17 hooks | Whole patched functions replace the stock ones: `drawSurface`, `renderBorder` ×2, `damageSurface`, `CWindow::{checkInputOnDecos, visibleOnMonitor, warpCursor}`, `CViewHitTester::{windowAt, windowSurfaceAt, surfaceLocalAt}`, `CInputManager::{mouseMoveUnified, processMouseDownNormal, onMouseWheel, sendMotionEventsToFocused}`, `CDragStateController::dragBegin`, `CPopup::{onMap, reposition}` |
| Hook registry, init (`main.cpp`, `Hooks.hpp`) | 104 lines | Every target is matched by its exact demangled signature before anything is hooked; any mismatch refuses the load |

For comparison the patch series adds 669 lines (489 in 0002–0009) in 9 patches. Total plugin: 639 hand-written lines,
2394 generated lines, 24 hooks.

Build: `scripts/build-plugin-spike.sh` (fresh build directory, O5 rules). Plugin `fcfaf0fc03e5…`, sources sha256
`49452668…`, git `81f941b`, GCC 16.2.1, 0 warnings. Two independent builds (manual, then the script in a fresh
directory) produced byte-identical `.so` files.

## Costs and risks the suite does not show

| Topic | Patch series | Plugin hooks |
|---|---|---|
| Upstream update | `git am`; conflicts and API changes fail at compile time | Regenerate the 17 copied functions from a patched upstream tree (`gen_copies.py` reads the patched draft tree, so the patch series is still maintained), rebuild, then a signature mismatch is found only at load time |
| Reaching internals | Normal C++ access | `#define private public` around every Hyprland header (`SpikeAccess.hpp`). Besides being an ODR violation, it can change C++03 POD-for-layout status and therefore tail-padding reuse in derived classes, a silent ABI mismatch; none was observed in the suite |
| Mechanism | Compiled code | x86_64 trampolines (`HookSystem.cpp`); the plugin must be built with the same compiler and the exact headers of the running binary |
| Seams a hook cannot reach | — | `updateRelativeCursorCoords` is file-static (absent from the dynamic symbol table): approximated in a `warpCursor` prologue. The camera hint around special-workspace windows (inline in `renderAllClientsForWorkspace`) is not covered. No test exercises either path |
| Logs | — | One false alarm during the spike: the nested log seemed to stop after loading; it was block buffering in the harness copy, fixed for all runs (e3a7d26) |
| Debugging | Source-level, compile errors on rebase | Behaviour differences surface at runtime only |

## Not verified

- Loading into the distribution's Hyprland binary (CachyOS `hyprland 0.56.2-4.1`): NOT RUN. The harness runs only agent-prefix
  binaries (never `$PATH`), and the plugin must match the running binary's API hash, which includes the dependency versions.
- Special workspaces, warp-on-focus and pointer constraints under a camera: NOT RUN for both delivery forms (no test).
- Physical hardware: NOT RUN (later phases).

## Recommendation for T071

Apply DV3-01 as approved: the spike meets its pass condition, so plugin delivery on stock Hyprland is selected. Before
the plugin becomes the production artifact, three items need a decision or work:
1. a load test against the actual distribution binary;
2. whether the private-member access is acceptable or the copied functions are reduced to public APIs and wrappers;
3. coverage for the special-workspace and warp paths.

If those costs are judged too high, the documented alternative is the patched Hyprland side by side. The patch series
stays the source of truth in both cases, because the plugin's copied functions are generated from it.
